# Acceptance records — 2026-11-23

## S5 devicebasedauth.org: resource-scoped grants — 2026-11-23

On `main`; verified locally against the fake issuer, not deployed.

- DBA grants limited by `resources` now apply to routes acting on one job, decided with resource
  `job:<name>`: the job's definition, run, pause/resume and triggers, and `GET /api/runs?job=`.
  Action-test histories (`_test:`), unfiltered runs, run details, actions and MCP get no resource,
  so such grants still reach nothing there.
- Order (`authorizeDba` in `src/auth/dba-online.js`): an offline resource grant (free) first, then
  an unrestricted online-only grant, then a resource grant DBA must decide, asked with the
  resource. The per-request `decide` is non-enumerable, so forwarded MCP identities drop it.
- Fixed in passing: responses from billed handlers (runs, changes) replaced the request's DBA
  decision and read charges with the handler's own `cost_microdollars`; the response now reports
  their sum, as `docs/devicebasedauth.md` already said.
- `npm test`: 68 files, 1,056 tests pass. New `src/auth/dba-resources.test.js`: resource naming per
  route; a `job:nightly-*` grant for read/run runs and reads `nightly-report` and is refused
  (`insufficient_scope`) on `weekly`, unfiltered runs, the account, action tests and changes; an
  expired resource grant is refused; a `require.online` resource grant answers `online_required`
  without `DBA_API_KEY`, and with it asks DBA once with `resource: job:nightly-report`, charges the
  decision and does not ask for other jobs; an offline resource grant wins over an online-only
  unrestricted one, which still applies to other jobs without a resource.
- `npm run lint`: clean. `npm run check:file-sizes`: pass. No route changes, so OpenAPI is unchanged.
- Not claimed: live acceptance with a real DBA credential (owner step 7 in `todo/dba_integration.md`).
