On `main`; verified locally against the fake issuer, not deployed.

## S4 retries reserved before their parent finalizes — 2026-11-23

On `main`; verified locally, not deployed.

- `JobDO.result()` reserves a failed run's retry right after settlement and finalizes the parent
  afterwards, instead of finalizing with a `retry.dispatch` outbox and clearing it. The parent's
  pending row already holds the retry input; redelivery and the pending alarm settle
  idempotently and find the deterministic `:retry` id. A budget/balance refusal commits the
  parent's final row and outcome in the pause transaction (one settings write). The parent then
  re-reads settings and keeps a finished retry's newer outcome. Legacy outbox rows still dispatch.
- Audit remeasured: worst run 35 → 33 writes (scheduled refused retry); manual 32, action test
  31, webhook 31 (excluding its surcharge write); DO requests unchanged at 27. `runRowWrites`
  35 → 33; rounded HTTP cost 50 → 48 µ$; run price 82 → 79 µ$ (DBA first attempt 86 µ$).
- Behaviour change, covered by tests: if the parent's final row fails after its retry was queued,
  that retry runs on Queue delivery rather than after recovery. `consumer.test.js` and
  `retention.test.js` now cover both a failed retry dispatch (retried after a 31-day outage) and a
  failed finalization (retry delivered at once; recovery does not dispatch or charge again).
  The alarm-recovery test makes the retry succeed and checks the parent does not overwrite its
  outcome (it fails without that guard). New test: a legacy outbox row is dispatched once and
  cleared.
- Fixed: `tests/jobs.spec.js` hardcoded the 85 µ$-based JS maximum, so the Playwright suite has
  failed since `808e13b`; it now computes the price with the workspace's formatting.
- `npm test`: 68 files, 1,059 tests pass. Playwright: 28/28. `npm run lint`: clean.
  `npm run check:file-sizes`: pass.
