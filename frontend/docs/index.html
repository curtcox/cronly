Define an action, then decide when it runs.

Getting started

  1. Sign in with your invitation and add prepaid credit on Account. The minimum is $5; card payment costs are shown on top.
  2. Save an HTTP action with a method, URL, headers and optional body. Or save a bundled JavaScript ES module.
  3. Create a job referencing that action. Use a five-field cron and an IANA time zone, or leave cron blank for on-demand and webhook use.
  4. Review the quote before saving or running. Set a daily and monthly budget. Inspect Runs for the outcome and charge.

Templates

{{var.base-url}}
{{secret.api-token}}
{{run.id}}  {{run.scheduled_at}}  {{run.trigger}}
{{job.name}}  {{account.id}}  {{input.message}}

Names use lowercase letters, numbers and hyphens, up to 64 characters. Unknown variables and secrets are rejected on save. Webhook input is a small JSON object with string values; missing fields refuse the run before execution.

Schedules and failures

Runs normally start within a few seconds of the scheduled minute. Time zones and daylight saving follow the pinned croner engine; preview the next five fires. Seconds cron is rejected. Overlap may skip or allow. Missed runs may skip or run once. Up to three immediate retries are separately reserved and billed.

Insufficient funds or budgets pause a schedule. A deposit resumes balance-paused schedules; budget windows reset at UTC day/month boundaries. Queue delivery is deduplicated before external execution. An uncertain or lost result expires at the held maximum; a redelivery does not repeat a claimed external call. Downstream services should also use the run ID as an idempotency key.

JavaScript

export default async function run(ctx) {
  const response = await ctx.fetch(ctx.vars["base-url"]);
  console.log("status", response.status);
  return { status: response.status };
}

ctx contains vars, secrets, run, input, job, account and fetch. No npm resolution: bundle dependencies yourself. Native networking is disabled. ctx.fetch uses a counted gateway and follows no redirects automatically. Configure 10–30,000 ms of CPU and 0–50 subrequests. Logs and return values are bounded and redacted.

Retention and export

Run logs retain at most 30 days or the latest 1,000 runs per job. Logs total at most 16 KB including metadata. Ledger and audit history are permanent, with cursor pagination. Export config JSON on Account, or runs as NDJSON. Secret values cannot be exported.
